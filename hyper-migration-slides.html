Key Steps: Traditional VMware / Hyper-V → KVM Migration

VMware (vSphere / ESXi)

  1. Export VM — OVF/OVA via ovftool or vSphere client
  2. Extract VMDK — untar OVA, locate disk files
  3. Convert — qemu-img convert -f vmdk -O qcow2
  4. Transfer — SCP to KVM host
  5. Create VM — virt-manager / virt-install
  6. Fix drivers, GRUB, fstab — manual debugging
  7. Remove VMware Tools — uninstall open-vm-tools

Hyper-V

  1. Shut down VM — ensure data consistency
  2. Convert — qemu-img convert -f vhdx -O qcow2
  3. Transfer — SCP / WinSCP to KVM host
  4. Create VM — map UEFI/Gen2 to OVMF
  5. Fix drivers — install VirtIO, fix network
  6. Remove Hyper-V services — integration components

Common Challenges (Both Platforms)

  • BSOD Missing VirtIO drivers → boot failure
  • Network VMXNet3 / Hyper-V vSwitch adapters gone
  • UEFI Gen2 / EFI VMs need OVMF in KVM
  • fstab Stale /dev/sdX names break mount
  • GRUB Wrong disk controller in bootloader
  • VMware Tools Conflicts with KVM guest agent
  • Snapshots VMDK chains must be flattened first
Each step is manual, error-prone, and must be repeated per VM.
Traditional tools (virt-v2v, qemu-img, StarWind) only convert — they don't fix.

The Manifest Contract: How They Communicate

Communication is file-based via a versioned JSON manifest. hypersdk produces it, h2kvm consumes it.

Design Principles

  • Provider-agnostic — h2kvm never talks to providers
  • Minimal requirements — only disks[] + firmware hint
  • Deterministic — same manifest → same outcome
  • Resumable — checksums enable idempotent ops
  • Backward compatible — within major version

Manifest Workflow

manifest-workflow/
  to_be_processed/  # Drop manifests here
  processing/       # Currently running
  processed/        # Completed
  failed/           # Errors

Hyper-V Migration: Step by Step

Phase 1: Export (hypersdk)

# Start daemon
hypervisord --config config.yaml

# Export Hyper-V VM
hyperctl export \
  --provider hyperv \
  --vm "web-server-01" \
  --output /exports/

# Or schedule recurring
hyperctl schedules create \
  nightly-export \
  "0 2 * * *" \
  --vm web-server-01
Produces: VHDX files + JSON manifest with VM metadata, firmware type, network config

Phase 2: Fix & Convert (h2kvm)

# YAML config
cmd: local
vmdk: /exports/web-01.vhdx
output_dir: /kvm
to_output: web-01.qcow2
out_format: qcow2
fstab_mode: stabilize-all
regen_initramfs: true
no_grub: false

# For Windows VMs
virtio_iso: /path/to/virtio.iso

# Run
sudo h2kvmctl \
  --config migration.yaml
Automated: Disk convert + OS inspect + bootloader fix + driver inject + fstab stabilize

Phase 3: Deploy

# Option A: libvirt
sudo virsh define web-01.xml
sudo virsh start web-01

# Option B: Direct to K8s
sudo h2kvmctl \
  --config migration.yaml \
  --deploy-k8s \
  --k8s-namespace prod \
  --k8s-vm-name web-01 \
  --k8s-auto-start

# Verify
sudo virsh domifaddr web-01
nc -zv <IP> 22
Result: VM boots first time, every time. Network, drivers, storage all working.

VMware Migration: Step by Step

Phase 1: Export (hypersdk)

# Configure vSphere credentials
export GOVC_URL='https://vcenter/sdk'
export GOVC_USERNAME='admin@vsphere'
export GOVC_PASSWORD='password'

# Start daemon
hypervisord --config config.yaml

# Export from vSphere
hyperctl export \
  --provider vsphere \
  --vm /dc1/vm/web-server \
  --format ova \
  --output /exports/

# Batch export entire folder
hyperctl export \
  --provider vsphere \
  --folder /dc1/vm/prod/ \
  --concurrent 4
Produces: VMDK/OVA files + JSON manifest. Supports CBT incremental export, snapshot management, resumable downloads.

Phase 2: Fix & Convert (h2kvm)

# YAML config
cmd: local
vmdk: /exports/web-server.vmdk
output_dir: /kvm
to_output: web-server.qcow2
out_format: qcow2
flatten: true
fstab_mode: stabilize-all
regen_initramfs: true
no_grub: false
compress: true
checksum: true

# Run
sudo h2kvmctl \
  --config migration.yaml
Handles: VMDK flatten (snapshot chains) + VMware Tools cleanup + VirtIO inject + GRUB repair + fstab stabilize

Phase 3: Deploy

# Option A: libvirt
sudo virsh define web-server.xml
sudo virsh start web-server

# Option B: Direct to K8s
sudo h2kvmctl \
  --config migration.yaml \
  --deploy-k8s \
  --k8s-namespace prod \
  --k8s-vm-name web-srv \
  --k8s-auto-start

# Option C: vSphere Python API
from h2kvm.vmware import \
    VMwareClient, ExportOptions
client = VMwareClient(
    vcenter_host='vcenter',
    username='admin@vsphere',
    password='pass'
)
await client.async_export_vm(
    vm_name='web-server',
    output_dir='/exports',
    export_mode='export'
)
