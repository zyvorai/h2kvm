Compute Isolation with cgroups v2

# Create tenant cgroup hierarchy
mkdir -p /sys/fs/cgroup/tenant-acme
mkdir -p /sys/fs/cgroup/tenant-globex

# Allocate 40% CPU to Tenant Acme (on 16-core host = 6.4 cores)
echo "640000 1000000" > /sys/fs/cgroup/tenant-acme/cpu.max

# Allocate 8 GB memory to Tenant Acme
echo "8589934592" > /sys/fs/cgroup/tenant-acme/memory.max

# Move VM processes into tenant cgroup (libvirt hook)
# /etc/libvirt/hooks/qemu:
#!/bin/bash
VM_NAME="$1"
ACTION="$2"
if [[ "$ACTION" == "started" ]]; then
  TENANT=$(grep -l "$VM_NAME" /etc/h2kvm/tenants/*/vms.list | head -1 | cut -d/ -f5)
  for pid in $(virsh qemu-monitor-command "$VM_NAME" --hmp info cpus | grep -oP 'thread_id=\K\d+'); do
    echo "$pid" > /sys/fs/cgroup/tenant-${TENANT}/cgroup.procs
  done
fi

Network Isolation

VLAN-Per-Tenant Model

  • Tenant Acme: VLAN 100-109 (10 VLANs reserved)
  • Tenant Globex: VLAN 200-209
  • Tenant Initech: VLAN 300-309
  • Management: VLAN 999 (host-only, no tenant access)
  • OVS trunk port carries all VLANs to physical switch
  • Each VM tagged to tenant's VLAN in libvirt XML

OVS Inter-Tenant Firewall

# Block all cross-tenant traffic
ovs-ofctl add-flow ovsbr0 \
  "priority=200,dl_vlan=100,\
   actions=mod_vlan_vid:100,normal"
ovs-ofctl add-flow ovsbr0 \
  "priority=100,dl_vlan=100,\
   nw_dst=10.200.0.0/16,actions=drop"
# VLAN 100 can't reach VLAN 200 subnet

Per-Tenant Migration Workflow

Migrate each tenant independently with isolated configs, networks, and storage.

Per-Tenant YAML Configuration

# tenant-acme-migration.yaml
tenant:
  name: acme-corp
  vlan_range: 100-109
  storage_pool: tenant-acme-pool   # LVM thin pool or Ceph pool
  cgroup: tenant-acme
  resource_limits:
    max_vcpus: 32
    max_memory_gb: 64
    max_storage_gb: 2000
    max_vms: 20

global:
  output_directory: /var/lib/libvirt/images/tenants/acme/
  format: qcow2
  compress: true
  fixes: { fstab: true, initramfs: true }

vms:
  - name: acme-db-primary
    source: { vmdk: /data/exports/acme/db-primary.vmdk }
    deploy: { memory: 16384, vcpus: 8, network_bridge: br-vlan100 }
    iotune: { total_iops_sec: 10000 }

  - name: acme-app-server
    source: { vmdk: /data/exports/acme/app-server.vmdk }
    deploy: { memory: 8192, vcpus: 4, network_bridge: br-vlan101 }
    iotune: { total_iops_sec: 5000 }

  - name: acme-web-frontend
    source: { vmdk: /data/exports/acme/web-frontend.vmdk }
    deploy: { memory: 4096, vcpus: 2, network_bridge: br-vlan102 }
    iotune: { total_iops_sec: 3000 }

KubeVirt Multi-Tenancy

Kubernetes namespaces provide native multi-tenant isolation for KubeVirt VMs.

Namespace-Per-Tenant Model

# Create tenant namespaces
kubectl create namespace tenant-acme
kubectl create namespace tenant-globex

# Resource quotas per tenant
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: ResourceQuota
metadata:
  name: tenant-quota
  namespace: tenant-acme
spec:
  hard:
    requests.cpu: "32"
    requests.memory: 64Gi
    limits.cpu: "48"
    limits.memory: 96Gi
    persistentvolumeclaims: "20"
    requests.storage: 2Ti
    count/virtualmachines.kubevirt.io: "20"
EOF

# Network policy: isolate tenant namespaces
kubectl apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-cross-tenant
  namespace: tenant-acme
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
      - namespaceSelector:
          matchLabels:
            tenant: acme
  egress:
    - to:
      - namespaceSelector:
          matchLabels:
            tenant: acme
    - to:    # Allow DNS
      - namespaceSelector: {}
        podSelector:
          matchLabels:
            k8s-app: kube-dns
      ports:
        - port: 53
          protocol: UDP
EOF

Billing & Usage Tracking

Metered billing from VM resource consumption for per-tenant invoicing.

Usage Metrics Collection

libvirt-based Metering

#!/usr/bin/env python3
# tenant-billing.py — collect usage per tenant
import libvirt
import json
from datetime import datetime

conn = libvirt.open('qemu:///system')
usage = {}

for dom in conn.listAllDomains():
    name = dom.name()
    tenant = name.split('-')[0]  # acme-db → acme
    stats = dom.getCPUStats(True)[0]
    blk = dom.blockStats('vda')
    net = dom.interfaceStats('vnet0')

    if tenant not in usage:
        usage[tenant] = {
            'cpu_seconds': 0,
            'disk_read_gb': 0,
            'disk_write_gb': 0,
            'net_rx_gb': 0,
            'net_tx_gb': 0,
            'vm_count': 0
        }
    usage[tenant]['cpu_seconds'] += stats['cpu_time'] / 1e9
    usage[tenant]['disk_read_gb'] += blk[1] / 1e9
    usage[tenant]['disk_write_gb'] += blk[3] / 1e9
    usage[tenant]['net_rx_gb'] += net[0] / 1e9
    usage[tenant]['net_tx_gb'] += net[4] / 1e9
    usage[tenant]['vm_count'] += 1

print(json.dumps(usage, indent=2))

Give tenants VM management capabilities without exposing host infrastructure.

Cockpit (Web UI for KVM)

  • Red Hat Cockpit with cockpit-machines plugin
  • Web-based VM console (VNC/SPICE via browser)
  • Start/stop/reboot VMs from web UI
  • Create snapshots, view performance graphs
  • RBAC: tenant sees only their VMs (polkit rules)
  • URL: https://host:9090/machines
  • No SSH access needed for tenant admins
  • Free, included with RHEL/Rocky/Fedora

oVirt / OLVM (Enterprise)

  • VMware vCenter equivalent for KVM
  • Multi-tenant with user portal per tenant
  • VM provisioning, templates, snapshots
  • Resource quotas enforced in UI
  • REST API for automation
  • Live migration, HA, load balancing
  • Oracle Linux Virtualization Manager (OLVM) = supported
  • Free (oVirt) or $1,200/host/yr (OLVM)

  • Kubernetes Dashboard or Rancher UI
  • Namespace isolation = tenant isolation
  • Tenant admin creates/manages VMs via UI
  • virtctl CLI for power users
  • Resource quotas shown in dashboard
  • Integrated with OIDC / LDAP auth
