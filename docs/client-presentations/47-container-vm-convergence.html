What Runs as Containers

  • Microservices (stateless, 12-factor apps)
  • APIs and web frontends
  • CI/CD runners (Jenkins, GitLab)
  • Monitoring stack (Prometheus, Grafana)
  • Message queues (Kafka, RabbitMQ)
  • New cloud-native applications

What Runs as VMs (KubeVirt)

  • Legacy applications (can't containerize)
  • Windows workloads (SQL Server, AD, IIS)
  • Databases requiring specific OS tuning
  • Appliances (firewalls, load balancers)
  • GPU workloads (passthrough)
  • Anything needing full OS isolation

VM as Kubernetes YAML

apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: db-server
  namespace: production
  labels:
    app: database
    tier: backend
spec:
  running: true
  template:
    metadata:
      labels:
        app: database
    spec:
      domain:
        cpu: { cores: 4 }
        memory: { guest: 8Gi }
        devices:
          disks:
            - name: rootdisk
              disk: { bus: virtio }
            - name: datadisk
              disk: { bus: virtio }
          interfaces:
            - name: default
              masquerade: {}
        resources:
          requests: { memory: 8Gi, cpu: "4" }
      networks:
        - name: default
          pod: {}
      volumes:
        - name: rootdisk
          persistentVolumeClaim: { claimName: db-server-root }
        - name: datadisk
          persistentVolumeClaim: { claimName: db-server-data }

Migration to KubeVirt

h2kvm converts VMware VMs and deploys directly to KubeVirt.

End-to-End Migration Pipeline

# Step 1: Export from VMware
h2kvmctl export --server vcenter.corp.com --vm db-server --output /data/exports/

# Step 2: Convert to QCOW2
h2kvmctl convert --source /data/exports/db-server.vmdk \
  --format qcow2 --fix-all --compress

# Step 3: Upload to KubeVirt via CDI
virtctl image-upload pvc db-server-root \
  --size=50Gi \
  --image-path=/data/exports/db-server.qcow2 \
  --uploadproxy-url=https://cdi-uploadproxy.cdi \
  --insecure

# Step 4: Deploy VM on KubeVirt
kubectl apply -f db-server-vm.yaml

# Step 5: Verify
virtctl console db-server
kubectl get vmi db-server -o wide
# NAME        AGE   PHASE     IP            NODE
# db-server   2m    Running   10.244.1.15   worker-01

# Or: h2kvmctl does steps 2-4 in one command:
h2kvmctl convert --source db-server.vmdk \
  --deploy-k8s --kubevirt-namespace production \
  --kubevirt-storage-class ceph-rbd

VM + Container Communication

  • VMs get pod IPs — routable within cluster
  • Kubernetes Services expose VMs like pods
  • kubectl expose vmi db-server --port=5432
  • Container apps connect to VM via Service DNS
  • psql -h db-server.production.svc.cluster.local
  • Network policies apply to VMs and pods equally
  • Service mesh (Istio) can include VMs

Gradual Migration Path

  • Phase 1: Migrate VMs from VMware → KubeVirt (lift-and-shift)
  • Phase 2: Containerize stateless apps (extract from VMs)
  • Phase 3: VMs remain for stateful/legacy only
  • Phase 4: All new apps are containers, VMs for legacy
  • No big-bang containerization needed
  • VMs and containers coexist permanently if needed
  • Migration velocity: your pace, not vendor's deadline

Platform Architecture Patterns

Three proven patterns for converged container + VM platforms.

Pattern 1: K3s + KubeVirt (Edge/Small)

  • Scale: 1-3 nodes, 5-30 VMs + containers
  • K8s distro: K3s (lightweight, single binary)
  • Storage: Longhorn or local NVMe
  • Network: Flannel + Multus for VM VLANs
  • Use case: Edge sites, remote offices, labs
  • Resource overhead: K3s + KubeVirt = ~2 GB RAM
  • Setup time: 30 minutes (quickstart.sh)
  • Cost: $0 software

Pattern 2: RKE2/OKD + KubeVirt (Enterprise)

  • Scale: 5-20 nodes, 50-200 VMs + containers
  • K8s distro: RKE2 or OKD (OpenShift community)
  • Storage: Ceph/Rook (replicated, HA)
  • Network: Calico + Multus + MetalLB
  • Use case: Production data center
  • HA: 3 control plane nodes, worker auto-scaling
  • Setup time: 1-2 days
  • Cost: $0 (OKD) or $50K/yr (OpenShift)

Pattern 3: OpenShift Virtualization

  • Scale: 10-100+ nodes, 200+ VMs + containers
  • K8s distro: OpenShift (Red Hat supported)
  • Storage: ODF (OpenShift Data Foundation / Ceph)
  • Network: OVN-Kubernetes + Multus
  • Use case: Enterprise with support requirements
  • Includes: Web console, VM templates, migration toolkit
  • Support: Red Hat 24/7 support included
  • Cost: $150K-$500K/yr (vs $350K+ VMware)

Choosing the Right Pattern

  • < 30 VMs, no support needed: K3s + KubeVirt
  • 30-200 VMs, some support: RKE2 + KubeVirt
  • 200+ VMs, full support: OpenShift Virtualization
  • Air-gapped: K3s (smallest footprint, offline install)
  • Multi-tenant MSP: RKE2 with namespace isolation
  • Regulated (SOX/HIPAA): OpenShift (certified)
  • All patterns use h2kvm for VM migration
  • Start with K3s POC → graduate to enterprise
