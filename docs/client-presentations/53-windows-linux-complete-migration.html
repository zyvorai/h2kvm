Windows Migration Deep Dive

The complete Windows offline fix pipeline — every stage explained.

Stage 1: Bootstrap

  • Mount disk offline via qemu-nbd
  • Detect Windows version (2016-2025, 10/11)
  • Detect boot mode (BIOS vs UEFI)
  • Detect storage controller (LSI/PVSCSI/storvsc)
  • Locate registry hives (SYSTEM, SOFTWARE)
  • Map partition layout (EFI, Recovery, C:)
  • Select VirtIO driver version for OS
  • Identify installed hypervisor tools

Stage 2: Driver Injection

  • Extract drivers from virtio-win ISO
  • Copy viostor/vioscsi .sys + .inf to C:\Windows
  • Copy NetKVM (network), Balloon (memory)
  • Load offline SYSTEM hive
  • Add registry entries (Start=0, boot-start)
  • Update CriticalDeviceDatabase for VirtIO PCI
  • Configure UpperFilters/LowerFilters
  • Set correct driver stack ordering

Stage 3: Cleanup & Verify

  • Remove VMware/Hyper-V/cloud services
  • Remove source hypervisor drivers
  • Update BCD for new boot controller
  • Enable serial console (COM1)
  • Generate libvirt XML (Q35 + VirtIO)
  • Generate KubeVirt manifest (optional)
  • Automated boot test (no BSOD check)
  • Webhook notification on result

SQL Server Licensing Savings with KVM

VMware Problem

VMware reports all physical cores to Microsoft. SQL per-core licensing counts host cores. A 2-socket 16-core host = 32 cores to license. Even 4-vCPU SQL VM may require all 32 cores licensed. SQL Enterprise: $15,123/core = $483,936/host.

KVM Advantage

KVM with CPU pinning exposes only assigned cores. 4 pinned vCPUs = license only 4 cores. NUMA-aware placement, cgroups enforce isolation (auditor-verifiable). SQL Enterprise: $15,123 x 4 = $60,492. Savings: $423K per host.

Boot Verification & Safety

Every migration — Windows and Linux — verified before production cutover.

Automated Boot Test

After conversion, h2kvm starts the VM on KVM, monitors boot progress, and confirms it reaches login (Windows) or shell (Linux). No human needs to watch. Fails are reported immediately with the error.

VNC/noVNC Console

Full graphical console for visual verification. See Windows desktop or Linux login prompt. Debug issues in real-time. Browser-based via noVNC — no client needed.

Post-Boot Health Checks

  • Disk I/O: VirtIO SCSI responding
  • Network: IP assigned, ports open
  • WIN RDP accessible on 3389
  • LIN SSH accessible on 22
  • Critical services running (SQL, httpd, etc.)
  • Event log / journal scan for errors
  • Serial console functional

Zero-Risk Rollback

  • Source disk preserved until verification
  • Original VM untouched on source platform
  • Conversion creates a copy — never modifies source
  • If boot fails: fix and retry, source is safe
  • Webhook alerts on success/failure
  • Auditable pass/fail report per VM
