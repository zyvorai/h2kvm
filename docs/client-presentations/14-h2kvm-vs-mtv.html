  • Heavy footprint: Not suitable for edge / small sites

Architecture Comparison

Modular platform vs monolithic operator.

h2kvm + hypersdk: Two-Layer Platform

  • hypersdk (Go daemon): Cloud API abstraction, 10 providers, hexagonal architecture with 13+ port interfaces
  • h2kvmctl (Python): Disk conversion, VMCraft guest fixes, libvirt XML generation, KubeVirt manifests
  • zkvm (Go TUI): Interactive terminal UI, vSphere discovery, live progress, file browser
  • Clean separation: Each layer can be used independently or together
  • Extensible: Add a new cloud provider by implementing one Go interface
  • Lightweight: No appliance boot, no supermin, pure Python + qemu-nbd

MTV: Kubernetes Operator

  • Single operator: Runs inside OpenShift as a set of pods
  • CRD-driven: Migration plans defined as custom resources
  • Depends on: OpenShift, OLM, OpenShift Virtualization, CDI, virt-v2v
  • VMware-focused: Primary support is vSphere, limited Hyper-V
  • No standalone use: Cannot run outside Kubernetes/OpenShift
  • Heavy dependencies: libguestfs appliance, virt-v2v, nbdkit stack

Enterprise Features MTV Doesn't Have

Capabilities that only h2kvm + hypersdk provides.

Standalone KVM Deploy

Generate optimized libvirt domain XML, virsh define, and boot test — all automated. MTV has zero standalone KVM capability. If you're migrating to traditional KVM/QEMU hosts, MTV simply cannot help.

Boot Verification

After conversion, h2kvm automatically starts the VM, verifies it boots, and reports status. MTV migrates the disk and hopes for the best — no automated boot test.

Interactive TUI (zkvm)

Terminal-based guided workflow with file browser, vSphere discovery, form fields, and live progress. MTV has a web UI — but it requires an OpenShift console and browser access.

Job Scheduling

hypersdk provides cron scheduling, time windows, priority queues, retry policies, and concurrency limits. Schedule migrations for off-peak hours. MTV has no scheduler.

Carbon-Aware Scheduling

Schedule migrations when grid carbon intensity is low. ESG compliance, sustainability reporting. No competitor — including MTV — offers this capability.

Cost Estimation

Estimate per-VM migration cost including compute, storage, and network. Budget planning before migration starts. MTV provides no cost visibility.

Webhook Notifications

Push migration events to Slack, Teams, PagerDuty, or any webhook endpoint. Track progress without watching a console. MTV has no notification system.

Cloud Repatriation

Export VMs from AWS, Azure, GCP, OCI — bring them on-prem to KVM or KubeVirt. MTV cannot touch cloud workloads. Only vSphere (and limited Hyper-V).

Prometheus Metrics

hypersdk exposes /metrics for migration throughput, job queue depth, error rates, and provider latency. Plug into existing Grafana dashboards. MTV has basic operator metrics only.

Pre-Flight Doctor

h2kvmctl doctor checks 9 system areas: disk space, dependencies, permissions, network, libvirt, KubeVirt readiness. MTV discovers issues at runtime.

VMCraft Engine

Pure Python + qemu-nbd for offline guest fixes. No libguestfs appliance boot (~30s overhead). Works on minimal Linux, containers, edge devices. MTV depends on libguestfs.

Dual-Target Pipeline

Same migration run can output both libvirt XML and KubeVirt manifest. Deploy the same VM to traditional KVM and Kubernetes simultaneously. MTV is KubeVirt-only.

Use Cases Where h2kvm Wins

Scenarios where MTV simply cannot compete.

1. VMware Exit to Standalone KVM

The most common migration target is plain KVM/libvirt — not Kubernetes. MTV cannot deploy to standalone KVM at all. h2kvm generates libvirt XML, defines the domain, and boot-tests it. This is the #1 use case MTV misses entirely.

2. Cloud Repatriation

Bring VMs home from AWS, Azure, GCP, or OCI. hypersdk exports from 10 cloud providers, h2kvmctl converts and deploys. MTV has zero cloud source support — it's VMware-to-OpenShift only.

3. Edge / Branch Office

50 retail stores each need 3-5 VMs migrated. h2kvm + K3s runs on a single server per site ($0). MTV requires a 6+ node OpenShift cluster per site ($50K+ per site). $2.5M vs $0.

4. Budget-Constrained Organization

Startup, government agency, or nonprofit that can't afford OpenShift. h2kvm is Proprietary (Zyvor AI Labs) — zero cost, forever. Full enterprise features without a subscription.

5. Multi-Cloud Consolidation

VMs scattered across VMware, AWS, and Azure — consolidate to on-prem KVM. One tool (h2kvm + hypersdk) handles all three sources. MTV can only handle VMware.

6. Air-Gapped / Classified

Defense, intelligence, or regulated environments with no internet. h2kvm is a single binary + Python package. MTV requires mirroring an entire OpenShift release + operator catalog — a multi-day project.

7. CI/CD Migration Pipeline

Automate VM migration in Jenkins/GitLab CI. h2kvm uses YAML configs and CLI commands. MTV requires kubectl + CRDs + operator lifecycle — far more complex to automate.

8. Hybrid Deploy (KVM + KubeVirt)

Some VMs go to traditional KVM hosts, others to KubeVirt. h2kvm handles both from the same pipeline with emit_domain_xml + deploy_k8s. MTV can only do KubeVirt — the KVM VMs need a different tool.
