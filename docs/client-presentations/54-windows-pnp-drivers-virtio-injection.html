Stage 1: Offline Pre-Injection

  • Mount disk via qemu-nbd + ntfs-3g
  • Detect OS from registry (ProductName, CurrentBuild)
  • Map architecture (x86 vs amd64)
  • Copy VirtIO .sys files to System32\drivers\
  • Stage INF+SYS in DriverStore\FileRepository\
  • Register OEM INF files in Windows\INF\
  • Edit SYSTEM hive (services, CriticalDeviceDatabase)
  • Edit SOFTWARE hive (RunOnce, OOBE bypass)
  • Disable VMware services in registry
  • Stage custom PNP drivers to C:\hyper2kvm-drivers

Stage 2: First Boot

  • Windows boots with VirtIO storage (Start=0)
  • Auto-login enabled (no password prompt)
  • Win11 OOBE bypass (BypassNRO, SkipMachineOOBE)
  • RunOnce batch file executes:
  •   1. pnputil installs VirtIO from ISO
  •   2. pnputil installs custom PNP drivers
  • Network apply script runs (PowerShell)
  • QEMU guest agent MSI installed (optional)
  • Serial console available on COM1

Stage 3: Verification

  • Automated boot test (no BSOD check)
  • Guest agent ping confirms drivers installed
  • Offline verification via NBD remount
  • Check: viostor.sys present & loaded
  • Check: netkvm.sys present
  • Check: balloon.sys present
  • Network connectivity verified
  • RDP accessible on port 3389
  • Generate production domain XML

Key innovation: All critical drivers are injected offline via direct registry editing. The VM boots with VirtIO storage already functional (Start=0). pnputil on first boot handles the PNP binding — but the boot itself never fails because the boot-critical driver is already registered.

Custom PNP Driver Injection

Stage any vendor-supplied driver for automatic PNP installation on first boot.

How It Works

  • Accepts directories or ISOs as driver sources
  • ISOs are auto-mounted and contents copied
  • All driver files staged to C:\hyper2kvm-drivers\
  • RunOnce registry key triggers pnputil on first boot
  • pnputil recursively discovers and installs all INF files
  • Supports multiple driver packages (repeatable flag)
  • Works alongside VirtIO driver injection

Use Cases

  • GPU passthrough: NVIDIA/AMD vendor drivers
  • Storage HBA: Fibre Channel, iSCSI drivers
  • Network: Mellanox, Intel vendor NICs
  • Smart cards: Security hardware drivers
  • Printers: Enterprise printer drivers
  • USB devices: Specialized peripherals
  • Custom hardware: Any INF-based driver

Configuration

YAML Config

# migration.yaml
custom_pnp_drivers:
  - /opt/drivers/nvidia-gpu/
  - /opt/drivers/mellanox-nic.iso
  - /opt/drivers/vendor-storage/

CLI

h2kvmctl --config migration.yaml \
  --custom-pnp-drivers /opt/nvidia-gpu/ \
  --custom-pnp-drivers /opt/mellanox.iso \
  --custom-pnp-drivers /opt/vendor-hba/

RunOnce Batch File (Staged in Registry)

@echo off
rem === VirtIO driver installation from ISO ===
for %%d in (D E F G H I J K L M N) do (
  if exist "%%d:\viostor" ( set ISO=%%d: & goto :found )
)
:found
rem Install: viostor NetKVM Balloon vioserial viorng qxldod viogpudo vioinput viofs pvpanic
for %%c in (viostor NetKVM Balloon vioserial viorng qxldod viogpudo vioinput viofs pvpanic smbus qemufwcfg) do (
  if exist "%ISO%\%%c\%OSFOLDER%\%ARCH%" (
    pnputil /add-driver "%ISO%\%%c\%OSFOLDER%\%ARCH%\*.inf" /install >nul 2>&1
  )
)
rem Install QEMU guest agent
if exist "%ISO%\guest-agent\qemu-ga-x86_64.msi" (
  msiexec /i "%ISO%\guest-agent\qemu-ga-x86_64.msi" /quiet /norestart
)

rem === Custom PNP driver installation ===
if exist "C:\hyper2kvm-drivers" (
  pnputil /add-driver "C:\hyper2kvm-drivers\*.inf" /subdirs /install
)

pnputil /subdirs recursively scans all subdirectories for INF files. This means you can drop an entire vendor driver package (with multiple architectures and versions) and pnputil will find and install the correct one for the running OS.

What Gets Captured

  • IP addresses (static and DHCP-assigned)
  • Subnet masks
  • Default gateways
  • DNS servers (static and DHCP-derived)
  • DNS suffix / domain
  • Interface profiles
  • DHCP vs Static mode per interface
  • All data from offline SYSTEM registry hive

Three Configuration Methods

  • Auto-preserve: Snapshot VMware config, apply to KVM NIC
  • Override file: --win-net-override /path/to/override.json
  • Inline JSON: --win-net-json '{"schema":1,...}'
  • YAML native: win_net: section in config
  • Adapter selection by MAC address or name
  • Supports both DHCP and static modes
  • Optional DNS override in DHCP mode

Configuration Examples

win_net:

  static:

Multi-Stage VirtIO Boot

The --virtio-deploy-boot flag enables a 4-stage automated deployment for maximum reliability.

Stage 1: Bootstrap Boot

  • SATA disk (safe, always works)
  • VirtIO NIC (triggers netkvm driver)
  • VirtIO balloon + serial + guest agent
  • VirtIO ISO attached as CD-ROM
  • UEFI firmware + NVRAM
  • OOBE auto-bypass configured
  • RunOnce batch installs all VirtIO drivers via pnputil
  • Custom PNP drivers installed via pnputil

Stage 2: Wait for Guest Agent

  • Polls virsh qemu-agent-command "guest-ping"
  • Default timeout: 180 seconds (configurable)
  • Guest agent confirms RunOnce has executed
  • All drivers installed and bound to devices
  • Network operational (DHCP or static applied)
  • VM is functional and accessible

Stage 3: Offline Verification

  • Shutdown VM cleanly
  • Remount QCOW2 via NBD
  • Verify critical files present:
  •   ✓ viostor.sys (critical)
  •   ✓ netkvm.sys (optional)
  •   ✓ balloon.sys (optional)
  •   ✓ vioser.sys (optional)
  • Fail fast if boot-critical driver missing

Stage 4: Production VM

  • Generate production libvirt domain XML
  • VirtIO disk + VirtIO NIC
  • Q35 machine type with PCIe
  • UEFI/BIOS as detected
  • Optional auto-start final VM
  • KubeVirt manifest (if deploy_k8s: true)
  • Webhook notification on completion

Configuration

# Enable multi-stage VirtIO boot deployment
virtio_deploy_boot: true
virtio_deploy_timeout: 300          # Wait up to 5 minutes for guest agent
no_virtio_deploy_start_final: false  # Auto-start production VM

# VirtIO ISO source
virtio_win_iso: /usr/share/virtio-win/virtio-win.iso

# Optional custom drivers (staged alongside VirtIO)
custom_pnp_drivers:
  - /opt/vendor-gpu-drivers/
  - /opt/vendor-storage.iso

# Network preservation
win_net:
  schema: 1
  mode: static
  static:
    ip: 10.0.1.50
    mask: 255.255.255.0
    gateway: 10.0.1.1
    dns_servers: ["10.0.1.53"]
