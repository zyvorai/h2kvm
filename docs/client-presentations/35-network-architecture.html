Linux Bridge Configuration

The simplest and most reliable network backend for KVM virtual machines.

Bridge Setup Methods

NetworkManager (RHEL 9 / Rocky 9)

# Create bridge
nmcli con add type bridge \
  con-name br0 ifname br0 \
  ipv4.addresses 10.0.1.1/24 \
  ipv4.gateway 10.0.1.254 \
  ipv4.dns 10.0.1.10 \
  ipv4.method manual

# Add physical NIC as port
nmcli con add type bridge-slave \
  con-name br0-port1 \
  ifname ens192 master br0

# VLAN bridge
nmcli con add type bridge \
  con-name br-vlan100 ifname br100
nmcli con add type vlan \
  con-name ens192.100 \
  ifname ens192.100 dev ens192 \
  id 100 master br100

systemd-networkd (Ubuntu / Minimal)

# /etc/systemd/network/10-br0.netdev
[NetDev]
Name=br0
Kind=bridge

# /etc/systemd/network/20-br0.network
[Match]
Name=br0
[Network]
Address=10.0.1.1/24
Gateway=10.0.1.254
DNS=10.0.1.10

# /etc/systemd/network/30-ens192.network
[Match]
Name=ens192
[Network]
Bridge=br0

# Apply
systemctl restart systemd-networkd

Bridge Performance Tuning

  • STP: Disable for VM-only bridges: ip link set br0 type bridge stp_state 0
  • Forward delay: ip link set br0 type bridge forward_delay 0
  • Multicast snooping: Disable if not needed: echo 0 > /sys/class/net/br0/bridge/multicast_snooping
  • TX queue: ip link set br0 txqueuelen 10000
  • GRO/GSO: ethtool -K br0 gro on gso on
  • Performance: ~8 Gbps on 10GbE with tuning
  • Latency: ~20us additional vs direct passthrough
  • Recommended for: most production workloads

OVS Configuration

# Install OVS
dnf install openvswitch3.1 && systemctl enable --now openvswitch

# Create OVS bridge with VLAN trunking
ovs-vsctl add-br ovsbr0
ovs-vsctl add-port ovsbr0 ens192 trunk=100,200,300
ovs-vsctl add-port ovsbr0 vnet0 tag=100    # VM on VLAN 100
ovs-vsctl add-port ovsbr0 vnet1 tag=200    # VM on VLAN 200

# Port mirroring (send all traffic to IDS VM)
ovs-vsctl -- set Bridge ovsbr0 mirrors=@m \
  -- --id=@vnet0 get Port vnet0 \
  -- --id=@vnet-ids get Port vnet-ids \
  -- --id=@m create Mirror name=ids-mirror select-all=true output-port=@vnet-ids

# QoS: limit VM to 1 Gbps
ovs-vsctl set Interface vnet0 ingress_policing_rate=1000000
ovs-vsctl set Interface vnet0 ingress_policing_burst=100000

# Libvirt OVS integration
# <interface type='bridge'>
#   <source bridge='ovsbr0'/>
#   <virtualport type='openvswitch'/>
#   <vlan><tag id='100'/></vlan>
#   <model type='virtio'/>
# </interface>

SR-IOV Setup

Enable SR-IOV Virtual Functions

# Enable IOMMU in kernel
# /etc/default/grub:
# GRUB_CMDLINE_LINUX="intel_iommu=on iommu=pt"
grub2-mkconfig -o /boot/grub2/grub.cfg

# Create 8 VFs on Intel X710
echo 8 > /sys/class/net/ens3f0/device/sriov_numvfs

# Persistent via udev rule
cat > /etc/udev/rules.d/70-sriov.rules <<'EOF'
ACTION=="add", SUBSYSTEM=="net", ENV{ID_NET_DRIVER}=="i40e", \
  ATTR{device/sriov_numvfs}="8"
EOF

# Verify VFs created
ip link show ens3f0
# 8 VFs listed as ens3f0v0..ens3f0v7

Bond Configuration

# LACP bond with NetworkManager (most common enterprise config)
nmcli con add type bond con-name bond0 ifname bond0 \
  bond.options "mode=802.3ad,miimon=100,lacp_rate=fast,xmit_hash_policy=layer3+4"

# Add slave interfaces
nmcli con add type ethernet con-name bond0-port1 ifname ens192 master bond0
nmcli con add type ethernet con-name bond0-port2 ifname ens224 master bond0

# Create bridge on top of bond (for VMs)
nmcli con add type bridge con-name br0 ifname br0 \
  ipv4.addresses 10.0.1.1/24 ipv4.method manual
nmcli con add type bridge-slave con-name br0-bond0 ifname bond0 master br0

# Verify LACP negotiation
cat /proc/net/bonding/bond0
# Partner Mac Address: 00:1c:73:xx:xx:xx (switch side)
# Aggregator ID: 1 (both ports in same aggregation)

Migration Tip: Bond Mode Selection

Active-backup (mode=1) is the safest migration choice — works with any switch, no switch-side config needed. Start with mode=1, then upgrade to LACP (mode=4) after validating switch compatibility. h2kvmctl auto-detects VMware NIC teaming policy from OVF and suggests the matching Linux bond mode in the migration report.

Firewall & Security Group Migration

Mapping VMware NSX distributed firewall rules to Linux nftables and libvirt nwfilter.

NSX → nftables Rule Translation

VMware NSX Rules (Source)

# NSX Distributed Firewall
Rule 1: Web-Tier → App-Tier
  Source: web-sg (10.0.1.0/24)
  Dest:   app-sg (10.0.2.0/24)
  Port:   TCP 8080, 8443
  Action: Allow

Rule 2: App-Tier → DB-Tier
  Source: app-sg (10.0.2.0/24)
  Dest:   db-sg  (10.0.3.0/24)
  Port:   TCP 5432 (PostgreSQL)
  Action: Allow

Rule 3: Default
  Source: Any
  Dest:   Any
  Action: Drop

Linux nftables (Target)

#!/usr/sbin/nft -f
table inet vm-firewall {
  chain forward {
    type filter hook forward
      priority 0; policy drop;

    # Web → App (TCP 8080, 8443)
    ip saddr 10.0.1.0/24
      ip daddr 10.0.2.0/24
      tcp dport { 8080, 8443 } accept

    # App → DB (TCP 5432)
    ip saddr 10.0.2.0/24
      ip daddr 10.0.3.0/24
      tcp dport 5432 accept

    # Established connections
    ct state established,related accept

    # Log + drop everything else
    log prefix "VM-FW-DROP: " drop
  }
}

OVS Flow-Based ACLs

# Micro-segmentation with OVS flows
# Allow web→app on port 8080
ovs-ofctl add-flow ovsbr0 \
  "priority=100,ip,\
   nw_src=10.0.1.0/24,\
   nw_dst=10.0.2.0/24,\
   tp_dst=8080,\
   actions=normal"

# Drop all other inter-tier traffic
ovs-ofctl add-flow ovsbr0 \
  "priority=50,ip,\
   nw_src=10.0.1.0/24,\
   nw_dst=10.0.3.0/24,\
   actions=drop"

# Default: allow same-subnet
ovs-ofctl add-flow ovsbr0 \
  "priority=10,actions=normal"

Zero-Downtime Network Cutover Strategy

Pre-Migration (T-1 week)

  • Inventory all VM IPs, MACs, VLANs, DNS records
  • Document DHCP reservations and static assignments
  • Lower DNS TTL to 60 seconds (from default 3600)
  • Configure KVM host bridges to match VLAN topology
  • Test network connectivity from KVM host to all VLANs
  • Verify routing tables and gateway accessibility

During Migration (T-0)

  • Shutdown VMware VM (clean shutdown, not force-off)
  • Start KVM VM with preserved MAC on same VLAN
  • DHCP: lease transfers automatically (same MAC = same IP)
  • Static IP: no change needed (same IP on same subnet)
  • ARP: gratuitous ARP sent on VM boot (updates switches)
  • Typical downtime: 2-5 minutes per VM

DNS Record Updates

  • If IP changes: update A/AAAA records
  • nsupdate -k /etc/rndc.key <<EOF
  • update delete vm1.example.com A
  • update add vm1.example.com 60 A 10.0.1.50
  • send
  • Reverse DNS (PTR): update if IP changed

Post-Migration Verification

  • ping -c 3 <vm-ip> — basic connectivity
  • arping -I br0 <vm-ip> — verify MAC on network
  • traceroute <vm-ip> — verify routing path
  • nmap -sV <vm-ip> — verify services responding
  • Restore DNS TTL to original value after 24 hours
  • Monitor for 48 hours before decommissioning VMware VM

Common Pitfalls & Fixes

MTU Mismatch (Most Common)

  • Symptom: SSH works but large transfers stall
  • Cause: VMware used jumbo frames (MTU 9000), KVM bridge defaults to 1500
  • Fix: Match MTU across path: ip link set br0 mtu 9000
  • Also set on physical NIC: ip link set ens192 mtu 9000
  • And in guest: ip link set eth0 mtu 9000
  • Verify: ping -M do -s 8972 <target>

IP Forwarding Disabled

  • Symptom: VMs can't reach outside subnet
  • Cause: Linux kernel drops forwarded packets by default
  • Fix: sysctl -w net.ipv4.ip_forward=1
  • Persistent: echo "net.ipv4.ip_forward=1" >> /etc/sysctl.d/99-kvm.conf
  • For IPv6: net.ipv6.conf.all.forwarding=1
  • Also check nftables isn't blocking FORWARD chain

Checksum Offload Issues

  • Symptom: tcpdump shows bad checksums, intermittent drops
  • Cause: Hardware offload mismatch between host and guest
  • Fix in guest: ethtool -K eth0 tx off rx off
  • Better fix: ensure virtio NIC has csum enabled
  • libvirt XML: <driver name='vhost' csum='on' gso='on'/>
  • Verify: ethtool -k eth0 | grep checksum

Bridge Filtering (iptables/nftables)

  • Symptom: Bridged traffic silently dropped
  • Cause: bridge-nf-call-iptables sends L2 traffic through L3 filter
  • Fix: Disable bridge filtering:
  • sysctl -w net.bridge.bridge-nf-call-iptables=0
  • sysctl -w net.bridge.bridge-nf-call-ip6tables=0
  • Or add explicit ACCEPT rules in FORWARD chain
