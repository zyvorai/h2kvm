Domain internal/domain

70+ canonical Go types — Job, ScheduledJob, VMInfo, ProviderConfig, CarbonIntensity, CostEstimate, Webhook, AuditEvent, Role, Secret. Depends only on Go stdlib (time, encoding/json). All other packages reference these types. This is the heart of the system.

Ports internal/ports

17+ interface contracts — ComputeProvider, ExportProvider, SnapshotProvider, JobStore, ScheduleManager, CarbonProvider, CostCalculator, AuthManager, SecretManager, WebhookSender, AuditLogger, Cache, and more. Defines what adapters must implement.

Adapters daemon/ + providers/

Concrete implementations — REST API server, SQLite job store, 10 cloud provider clients, Prometheus metrics, webhook dispatcher, rate limiter, cron scheduler, carbon data fetcher, cost calculator. Swappable without touching business logic.

Domain Layer — Pure Business Types

Zero dependencies. Every type in internal/domain is a plain Go struct — no imports beyond stdlib.

Provider Interface (Go Code)

// ComputeProvider — VM discovery and management
type ComputeProvider interface {
    Name() string
    Type() domain.ProviderType
    Connect(ctx context.Context, config domain.ProviderConfig) error
    Disconnect(ctx context.Context) error
    ValidateCredentials(ctx context.Context) error
    ListVMs(ctx context.Context, filter domain.VMFilter) ([]*domain.VMInfo, error)
    GetVM(ctx context.Context, identifier string) (*domain.VMInfo, error)
    SearchVMs(ctx context.Context, query string) ([]*domain.VMInfo, error)
}

// ExportProvider — VM disk export
type ExportProvider interface {
    ExportVM(ctx context.Context, id string, opts domain.ExportOptions) (*domain.ExportResult, error)
    GetExportCapabilities() domain.ExportCapabilities
}

// FullProvider — providers that support both discovery and export
type FullProvider interface {
    ComputeProvider
    ExportProvider
}

Daemon Services — daemon/

The daemon layer contains all infrastructure adapters: REST API, job engine, scheduler, storage, auth, and observability.

daemon/api

  • REST API server (net/http)
  • OpenAPI 3.0 spec (openapi.yaml)
  • JSON request/response
  • Versioned routes (/api/v1/...)
  • CORS, compression, request ID
  • Health + readiness endpoints

daemon/jobs

  • Job lifecycle: create, run, cancel
  • Concurrent execution with limits
  • Progress tracking per job
  • Webhook notification on state change
  • Implements ports.JobManager
  • Automatic cleanup of old jobs

daemon/scheduler

  • Cron-based scheduling engine
  • Time window enforcement
  • Job dependencies (DAG)
  • Priority queues (0-100)
  • Retry with exponential backoff
  • Carbon-aware scheduling mode

daemon/store

  • SQLite persistent storage
  • Implements JobStore + ScheduleStore
  • Schema migrations
  • Transaction support
  • Query filtering (status, date, provider)
  • Backup/restore capability

daemon/auth

  • JWT token authentication
  • API key authentication
  • Session management
  • RBAC: admin, operator, viewer
  • Password hashing (bcrypt)
  • Token rotation and expiry

daemon/rbac

  • Role-based access control
  • Actions: create, read, update, delete, export, cancel
  • Resources: jobs, schedules, providers, config
  • Permission matrix per role
  • Middleware integration
  • Audit log on denied access

daemon/metrics

  • Prometheus /metrics endpoint
  • Job counters (created, completed, failed)
  • Export duration histograms
  • Provider latency gauges
  • Queue depth metrics
  • System resource metrics

daemon/webhooks

  • Event-driven notifications
  • Slack, Teams, PagerDuty, custom
  • Retry with backoff on failure
  • Event filtering per webhook
  • Conversion started/completed/failed
  • Job lifecycle events

daemon/secrets

  • Secret management with rotation
  • Backends: file, env vars, vault
  • Cached secret access
  • Automatic rotation support
  • Health check for secret backends
  • Provider credential storage

daemon/audit

  • Full audit trail
  • Events: login, export, create/cancel/delete job
  • User, IP, timestamp per event
  • File-based logger
  • Queryable history
  • Compliance-ready (SOX, HIPAA)

daemon/cache

  • Generic key-value cache
  • TTL-based expiration
  • VM inventory caching
  • Provider response caching
  • Reduces cloud API calls
  • Configurable cache size

daemon/ratelimit

  • HTTP request rate limiting
  • Per-user and global limits
  • Token bucket algorithm
  • Protects cloud API quotas
  • 429 Too Many Requests response
  • Configurable per endpoint

Carbon, Cost & Scheduling

Enterprise features no competitor offers.

Carbon-Aware Scheduling

  • CarbonProvider port: Fetches real-time grid carbon intensity from ElectricityMap or WattTime APIs
  • 12 grid zones: US East/West/Central, EU Central/West/North, APAC Singapore/Tokyo/Sydney/India, China Beijing/Shanghai
  • Thresholds: Excellent (<100 gCO2/kWh), Good (<200), Moderate (<400), Poor (<600)
  • Scheduling: Delay migration jobs until carbon intensity drops below threshold
  • Forecasting: GetForecast returns hourly predictions — schedule for greenest window
  • Reporting: GenerateCarbonReport shows CO2 saved by scheduling optimally
  • ESG compliance: Documented carbon savings for sustainability reporting

Cost Estimation

  • CostCalculator port: Estimates cloud storage and transfer costs per migration
  • 6 cloud providers: S3, Azure Blob, GCS, OCI, Backblaze, Wasabi
  • Storage tiers: S3 Standard/IA/Glacier, Azure Hot/Cool/Archive, GCS Standard/Nearline/Coldline
  • EstimateCost: Per-VM cost including storage, transfer, API calls
  • CompareProviders: Side-by-side cost comparison across clouds
  • ProjectYearlyCost: Annual cost projection for ongoing storage
  • EstimateExportSize: Predicted export size based on disk, format, snapshots

Advanced Scheduling

  • Cron expressions: Standard 5-field cron for recurring jobs
  • Time windows: Restrict execution to off-peak hours (e.g., 2AM-6AM)
  • Job dependencies: DAG-based — job B runs only after job A succeeds
  • Priority queues: 0 (lowest) to 100 (highest) — critical VMs first
  • Retry policies: Max retries, exponential backoff, retry delay
  • Concurrency limits: Max parallel exports per provider
  • TriggerNow: Manual override to run scheduled job immediately

Observability Stack

  • Prometheus metrics: /metrics endpoint with job, export, provider metrics
  • Structured logging: JSON format with trace IDs for request correlation
  • Audit trail: Every action logged: who, what, when, from where
  • OpenTelemetry: Distributed tracing via daemon/tracing
  • Dashboard: React web UI (hypersdk-dashboard) for real-time monitoring
  • Grafana-ready: Pre-built dashboard templates for common metrics
  • Alerting: Webhook notifications integrate with PagerDuty/Slack/Teams

Why This Architecture Matters

Technical advantages of hexagonal design for enterprise migration.

Add a New Provider in Hours, Not Weeks

Implement ComputeProvider + ExportProvider (6-8 methods). Register in providers/registry.go. Done. No changes to daemon, scheduler, API, or any other code. The hexagonal boundary means new providers are isolated, testable, and independently deployable.

Swap Any Adapter Without Risk

Replace SQLite with PostgreSQL? Implement JobStore interface. Switch from file-based secrets to HashiCorp Vault? Implement SecretManager. Replace Prometheus with Datadog? Implement SystemMetrics. Business logic never changes.

Domain Logic Is 100% Testable

internal/domain has zero external dependencies — it's pure Go structs with validation logic. Every port interface can be mocked trivially. Integration tests use real adapters. Unit tests use mocks. Full coverage without infrastructure.

Enterprise-Grade Security

RBAC with 3 roles (admin/operator/viewer), 6 actions, resource-level permissions. JWT + API key auth. Secret rotation. Full audit trail (SOX/HIPAA-ready). TLS everywhere. Rate limiting per user and endpoint. All via clean port interfaces.
