Cross-Distro Challenges Solved

QEMU Binary Path

AlmaLinux uses /usr/libexec/qemu-kvm instead of Fedora's /usr/bin/qemu-system-x86_64. hyper2kvm auto-detects the correct binary across Fedora, RHEL, AlmaLinux, Debian, and Ubuntu.

Graphics Backend

AlmaLinux QEMU is built without SPICE support. hyper2kvm detects this and falls back to VNC automatically — no user configuration needed.

Netplan VMware NIC Names

Ubuntu VMs use ens33 (VMware PCI slot). On KVM it becomes ens3. hyper2kvm replaces hardcoded names with match: name: "en*" for universal compatibility.

Initramfs VirtIO Injection

VMware VMs ship without virtio drivers in initramfs. hyper2kvm runs dracut --add-drivers virtio_blk virtio_net... inside the guest via chroot to ensure first-boot success.

Demo script: run-demo.sh <vmdk-path> — single command handles cleanup, conversion, offline fixes, libvirt define, VM boot, and IP verification.

3. Ubuntu Server 22.04 LTS (Jammy Jellyfish)

Server LTS with netplan DHCP on ens33 (VMware) — demonstrates automatic netplan NIC name fix.

Source
Source:    UbuntuServer_22.04_VM_LinuxVMImages.COM.vmdk (4.1 GiB)
Format:    VMware monolithicSparse VMDK
Layout:    MBR → /boot (1M+2G) + LVM (ubuntu-vg: ubuntu-lv 100G)
Kernel:    5.15.0-30-generic
Network:   netplan with hardcoded ens33 (VMware PCI slot name)
The Problem & The Fix

Before (VMware)

# /etc/netplan/00-installer-config.yaml
network:
  ethernets:
    ens33:          # ← VMware-specific name
      dhcp4: true
  version: 2

On KVM, the NIC becomes ens3 — netplan won't match ens33, so no network.

After (hyper2kvm auto-fix)

# /etc/netplan/00-installer-config.yaml
network:
  ethernets:
    all-en:
      dhcp4: true
      match:
        name: en*    # ← matches any backend
  version: 2

hyper2kvm detects VMware NIC names (ens33, ens160, etc.) and replaces with wildcard match. Works everywhere.
