The Windows BSOD Problem

Why Windows VMs fail after naive VMware-to-KVM migration.

Without proper driver injection, Windows VMs BSOD on first boot

Windows kernel loads storage drivers at boot time based on registry entries. VMware uses LSI Logic or PVSCSI controllers. KVM uses VirtIO. If VirtIO drivers aren't injected before migration, Windows can't see the boot disk and blue-screens with INACCESSIBLE_BOOT_DEVICE (0x7B).

Enterprise Windows Workloads

Special considerations for critical Windows applications.

🗄️

SQL Server

Migration safe: SQL Server data files migrate with the disk. No reinstall needed. VirtIO SCSI provides comparable I/O performance to PVSCSI.
Licensing win: Moving from VMware to KVM may reduce SQL Server licensing costs — KVM hosts are often counted more favorably for per-core licensing.

📂

Active Directory DCs

Approach: Migrate secondary DCs first. Verify replication. Then migrate primary. Never migrate all DCs simultaneously.
hyper2kvm handles: NIC MAC preservation optional, DNS settings intact, AD database files migrate with disk.

📧

Exchange Server

Tested: Exchange 2016/2019 migrated successfully. Database mounts correctly after VirtIO driver injection. Recommend maintenance mode during migration window.

🌐

IIS / Web Servers

Simplest migration: No special handling needed beyond standard VirtIO injection. Sites and app pools start automatically after boot. Verify bindings post-migration.
