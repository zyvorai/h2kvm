Go Backend (h2kweb)

  • chi router with middleware (CORS, auth, logging)
  • PAM authentication — system-level credentials
  • HttpOnly cookies with SameSite=Strict
  • 32-byte random session tokens
  • WebSocket hub for real-time log streaming
  • libvirt integration via go-libvirt bindings

React/TypeScript Frontend

  • Vite build system with hot module replacement
  • TailwindCSS + shadcn/ui component library
  • Dark and light theme support
  • Responsive layout (desktop + tablet)
  • WebSocket client for live migration logs
  • noVNC integration for VM console access

API Endpoints

  • POST /api/auth/login
  • GET /api/dashboard
  • GET /api/vms
  • POST /api/migrate
  • GET /api/jobs/:id/logs
  • WS /api/ws

Security

  • PAM auth (same as SSH credentials)
  • Session-based with secure cookies
  • CSRF protection via SameSite
  • No default passwords
  • Optional API key for automation

Integration

  • libvirt: domain CRUD, screenshots
  • h2kvmctl: migration subprocess
  • govc: VMware vSphere discovery
  • KubeVirt: Kubernetes VM deploy
  • systemd: service management

2. Dashboard Overview

Single-pane view of migration pipeline, host resources, readiness checks, and recent activity.

Migration Pipeline

  • Active migrations with real-time progress bars
  • Queued, running, completed, and failed job counts
  • Per-job elapsed time and ETA
  • Click-through to full job logs
  • Cancel in-progress migrations

Host Resources

  • CPU: model, cores, current load average
  • Memory: total, used, available with percentage
  • Disk: per-mount usage with warnings at 90%+
  • QEMU version and KVM status
  • libvirt connection state

Readiness Checks (19 Items)

  • KVM hardware acceleration available
  • QEMU binary found and executable
  • libvirt daemon running and accessible
  • qemu-nbd and nbd kernel module loaded
  • virtio-win ISO present and valid
  • OVMF firmware files found
  • hivex Python bindings available
  • Sufficient disk space for conversions
  • Network bridge or NAT configured

Disk Images Inventory

  • Scan configured directories for VMDK, OVA, QCOW2
  • File size, format, and modification date
  • Quick-action: migrate selected image
  • Delete or move completed conversions
  • Storage usage summary per directory

All 19 readiness checks must pass before migrations can start. The dashboard shows a clear green/amber/red status for each check, with remediation hints for any failures.

File Upload

  • Drag-and-drop zone for VMDK, OVA, VHD files
  • Up to 50 GB upload size supported
  • Real-time upload progress bar with percentage
  • Cancel upload mid-transfer
  • Chunked upload for reliability over slow connections

3-Step Wizard

  • Step 1: Source — file path, format auto-detect
  • Step 2: Options — output dir, flatten, compress, fixes
  • Step 3: Deploy — libvirt XML, virsh define, boot test
  • YAML preview panel shows generated config
  • All h2kvmctl options exposed in advanced section
  • Save and reuse migration templates

Live Logs

  • WebSocket streaming of h2kvmctl stdout/stderr
  • Auto-scroll follows latest output
  • Progress bar with percentage, speed, and ETA
  • Color-coded: info (blue), warning (amber), error (red)
  • Search within log output
  • Download full log as text file

Report Export

  • Migration summary report (JSON and text)
  • Source and destination details
  • Duration, disk sizes, conversion ratio
  • Fixes applied (drivers, initramfs, GRUB)
  • Deploy result: domain name, IP address
  • Shareable link to migration result page

6. Deployment

One-command remote deployment, systemd service, watch directory daemon, and theme support.

deploy-remote.sh

# One-command setup on any Linux host
curl -sL https://raw.githubusercontent.com/
  ssahani/hyper2kvm/main/scripts/
  deploy-remote.sh | bash -s -- \
    --host 10.0.1.50 \
    --user root
  • rsync project files to remote host
  • pip install with dependency resolution
  • hivex source rebuild for Python 3.12
  • virtio-win ISO auto-download
  • systemd service installation

Daemon Service

# Watch directory for auto-conversion
[Service]
ExecStart=/usr/local/sbin/h2kvmctl \
  --daemon \
  --watch-dir /var/lib/hyper2kvm/incoming \
  --output-dir /var/lib/hyper2kvm/converted \
  --auto-deploy
  • inotify watch on incoming directory
  • Auto-convert dropped VMDK/OVA/VHD files
  • Auto-deploy to libvirt after conversion
  • Configurable concurrency (default: 1)

h2kweb systemd

  • Unit: h2kweb.service
  • Default port: 5070
  • Auto-restart on failure
  • Journal logging integration
  • Socket activation support

Dark / Light Theme

  • System preference auto-detection
  • Manual toggle in header
  • Persistent via localStorage
  • All components themed
  • Chart colors adapt

Configuration

  • --binary: h2kvmctl path (auto-detect)
  • --addr: listen address (:5070)
  • --api-key: optional API auth
  • --static-dir: frontend assets
  • --tls-cert/key: HTTPS
