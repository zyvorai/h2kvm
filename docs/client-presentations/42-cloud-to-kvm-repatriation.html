When to Repatriate

  • Steady-state workloads (predictable, not bursty)
  • Data-heavy applications (storage + egress costs dominate)
  • Compliance requirements (data residency, air-gap)
  • Performance-sensitive (latency, GPU, bare-metal needs)
  • Cloud bill growing > 20% annually without new workloads
  • Multi-year commitments expiring (RI/savings plans ending)

When to Stay in Cloud

  • Highly variable workloads (autoscaling critical)
  • Global presence needed (30+ regions)
  • Managed services dependency (RDS, Lambda, etc.)
  • Small footprint (< 20 VMs — cloud is simpler)
  • No DC operations expertise on staff
  • Short-lived workloads (< 12 months)

AWS VM Export

Exporting EC2 instances and AMIs for conversion to KVM.

AWS Export Methods

Method 1: VM Export (create-instance-export-task)

# Export running EC2 instance to S3
aws ec2 create-instance-export-task \
  --instance-id i-0123456789abcdef0 \
  --target-environment vmware \
  --export-to-s3-task \
    DiskImageFormat=vmdk,\
    ContainerFormat=ova,\
    S3Bucket=my-export-bucket,\
    S3Prefix=exports/

# Monitor export progress
aws ec2 describe-export-tasks \
  --export-task-ids export-i-0123456789

# Download from S3
aws s3 cp s3://my-export-bucket/exports/export-i-012.ova ./

# Convert with h2kvmctl
h2kvmctl convert --source export.ova \
  --format qcow2 --fix-all --deploy-libvirt

Method 2: EBS Snapshot → Raw Image

# Create snapshot of EBS volume
aws ec2 create-snapshot \
  --volume-id vol-0123456789abcdef0 \
  --description "Repatriation export"

# Share snapshot to S3 (via EBS direct API)
aws ebs get-snapshot-block \
  --snapshot-id snap-0123456789 \
  --block-index 0 --block-token xxx

# Or: attach snapshot to helper EC2, dd to S3
# Faster for large disks
aws ec2 create-volume --snapshot-id snap-012 \
  --availability-zone us-east-1a
# Attach to helper → dd if=/dev/xvdf | gzip | \
#   aws s3 cp - s3://bucket/disk.raw.gz

# Convert raw to QCOW2
h2kvmctl convert --source disk.raw \
  --format qcow2 --fix-all

Azure VM Export

Exporting Azure VMs as VHD/VHDX for conversion to KVM.

Azure Export Workflow

# Step 1: Deallocate VM (required for export)
az vm deallocate --resource-group myRG --name my-vm

# Step 2: Generalize (optional — skip if preserving identity)
# az vm generalize --resource-group myRG --name my-vm

# Step 3: Get SAS URL for managed disk download
DISK_ID=$(az vm show -g myRG -n my-vm --query "storageProfile.osDisk.managedDisk.id" -o tsv)
az disk grant-access --duration-in-seconds 86400 --ids $DISK_ID --query accessSas -o tsv
# Returns: https://md-xxx.blob.core.windows.net/xxx?sv=...&sig=...

# Step 4: Download VHD (use azcopy for speed)
azcopy copy "https://md-xxx.blob.core.windows.net/xxx?sv=...&sig=..." ./my-vm.vhd

# Step 5: Convert VHD to QCOW2 with h2kvmctl
h2kvmctl convert --source my-vm.vhd --format qcow2 \
  --fix-fstab --fix-initramfs --fix-network \
  --emit-domain-xml --deploy-libvirt

# Step 6: Revoke SAS access
az disk revoke-access --ids $DISK_ID

Azure-Specific Fixes

Linux VMs from Azure

  • waagent: Azure Linux Agent — disable/remove
  • systemctl disable walinuxagent && dnf remove WALinuxAgent
  • cloud-init Azure datasource: disable
  • rm /etc/cloud/cloud.cfg.d/10_azure.cfg
  • Hyper-V drivers: hv_vmbus, hv_storvsc, hv_netvsc
  • h2kvmctl replaces with virtio drivers in initramfs
  • Swap: Azure creates swap on resource disk — configure locally
  • NTP: Remove Azure-specific chrony config

Windows VMs from Azure

  • Azure Guest Agent: uninstall from Programs
  • Hyper-V IC: Integration Components stay (harmless)
  • VirtIO drivers: inject with h2kvmctl --virtio-drivers
  • Activation: Azure KMS won't work on-prem
  • Re-activate with on-prem KMS or MAK key
  • RDP: works immediately (same settings preserved)
  • Azure AD: if joined, may need to rejoin on-prem AD
  • Disk format: Azure exports as fixed VHD (fast convert)

GCP VM Export

Exporting Google Compute Engine instances for KVM conversion.

GCP Export Methods

Method 1: gcloud export (Recommended)

# Export VM disk to GCS as VMDK
gcloud compute images export \
  --destination-uri gs://my-bucket/exports/vm-disk.vmdk \
  --image my-vm-image \
  --export-format vmdk

# Or export as raw (faster, larger)
gcloud compute images export \
  --destination-uri gs://my-bucket/exports/vm-disk.raw.tar.gz \
  --image my-vm-image \
  --export-format raw

# Download from GCS
gsutil cp gs://my-bucket/exports/vm-disk.vmdk ./

# Convert
h2kvmctl convert --source vm-disk.vmdk \
  --format qcow2 --fix-all --deploy-libvirt

Method 2: Disk Snapshot → Image → Export

# Create snapshot of running VM's disk
gcloud compute disks snapshot my-vm-disk \
  --snapshot-names my-vm-snap \
  --zone us-central1-a

# Create image from snapshot
gcloud compute images create my-vm-image \
  --source-snapshot my-vm-snap

# Export image (as above)
gcloud compute images export \
  --destination-uri gs://bucket/vm.vmdk \
  --image my-vm-image \
  --export-format vmdk

# Clean up
gcloud compute images delete my-vm-image
gcloud compute snapshots delete my-vm-snap

Compress Before Download

# Saves 40-60% on egress costs

# AWS: compress in EC2 before S3
ssh ec2-helper "qemu-img convert -c \
  -f raw -O qcow2 /dev/xvdf disk.qcow2"
# Upload compressed to S3, download compressed

# Typical compression ratios:
# Linux VM: 60-70% reduction
# Windows VM: 40-50% reduction
# Database VM: 50-60% reduction
# Empty space: 95%+ reduction
