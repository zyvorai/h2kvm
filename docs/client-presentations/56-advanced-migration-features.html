LUKS2 Encryption & Storage

Migrate VMs to encrypted disks with automatic TPM enrollment — zero-touch encryption for confidential compute.

LUKS2 + TPM Pipeline

  • End-to-end: VMDK → LUKS2 container → filesystem migration
  • AES-XTS-plain64 encryption, SHA256 hashing
  • Argon2id PBKDF (memory-hard key derivation)
  • Key management: keyfiles or TPM auto-unlock
  • TPM2 enrollment for seamless boot
  • initramfs rebuild with dm_crypt + xts modules
  • Targets: OpenShift confidential VMs, Talos, Flatcar

Configuration

# Enable LUKS encryption
luks_enable: true
luks_passphrase: "encryption-key"
# Or use environment variable:
luks_passphrase_env: LUKS_KEY
# Or use keyfile:
luks_keyfile: /path/to/keyfile
luks_mapper_prefix: "h2kvm"

# initramfs auto-includes:
#   dm_crypt, xts, dm_mod

LVM Handling — Container-Isolated

Two-Phase Activation

  • Phase 1: Container-isolated VG discovery
  • Podman/Docker with private LVM dirs
  • No --privileged, targeted capabilities
  • --network=none for security
  • Phase 2: Host-side DM table activation
  • Device filter regex per NBD device
  • Prevents host VG cache pollution

Safety Features

  • Per-job LVM_SYSTEM_DIR isolation
  • File lock per NBD device (no collisions)
  • Stale NBD recovery on startup
  • Deactivation of stale VGs before re-activation
  • udev settling + dmsetup + 200ms buffer
  • 30-second timeout per operation
  • Auto-install podman/docker if missing

Batch Migration & Daemon Mode

Orchestrate hundreds of VMs with parallel workers, checkpoint/resume, and file system watching.

Batch Orchestrator

  • Parallel execution with configurable worker limit
  • Priority-based VM ordering
  • Per-VM error isolation (continue-on-error)
  • Shared config + per-VM overrides
  • Aggregate progress reporting
  • JSON and YAML manifest formats
# batch-manifest.yaml
batch_version: 1
batch_metadata:
  batch_id: "vmware-exit-2026"
  parallel_limit: 4
  continue_on_error: true
shared_config:
  output_dir: /data/converted
  out_format: qcow2
  regen_initramfs: true
  emit_domain_xml: true
vms:
  - name: web-01
    vmdk: /exports/web-01.vmdk
    priority: 1
  - name: db-primary
    vmdk: /exports/db-primary.vmdk
    priority: 2
    memory: 16384
    vcpus: 8

Checkpoint / Resume

  • Automatic checkpoint after each VM completion
  • Atomic writes (temp + replace for safety)
  • Per-VM granularity — skip completed/failed VMs
  • Re-run same command to resume
  • Auto-cleanup after successful batch
# Checkpoint file (auto-generated):
# .checkpoints/checkpoint-vmware-exit-2026.json
{
  "batch_id": "vmware-exit-2026",
  "completed_vms": ["web-01", "web-02"],
  "failed_vms": ["legacy-app"],
  "resume_from": 3,
  "total_vms": 50
}

# Resume: just re-run the same command
h2kvmctl --batch-manifest batch.yaml
# Skips web-01, web-02, legacy-app
# Continues from VM #4

Daemon / Watch Mode

3-Directory Workflow

  • to_be_processed/ — Drop zone for manifests
  • processing/ — Currently processing
  • processed/ — Completed with reports
  • failed/ — Failed with error context
  • File system watcher (watchdog library)
  • Supports .json, .yaml, .yml manifests
  • File deduplication tracking

Daemon Features

  • Concurrent processing (ThreadPoolExecutor)
  • Statistics tracking (duration, throughput)
  • Detailed reporting with artifact tracking
  • Signal handling (SIGTERM, SIGINT)
  • Systemd service integration
  • Thread-safe processing queue

Systemd Service

# h2kvm@.service
[Unit]
Description=h2kvm daemon

[Service]
ExecStart=/usr/local/sbin/h2kvmctl \
  --manifest-workflow-mode \
  --manifest-workflow-dir %i
Restart=on-failure

[Install]
WantedBy=multi-user.target

# Enable:
systemctl enable --now \
  h2kvm@/data/migrations
