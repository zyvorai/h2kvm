Why Move to the Edge?

Centralized data centers and cloud are expensive, slow, and fragile for distributed workloads.

VMware Licensing Crisis

Broadcom's acquisition of VMware caused 2-10x license increases. Running vSphere at 50 branch offices now costs $500K-$2M/year in software alone. Edge sites don't need enterprise hypervisor overhead.

Cloud Egress Costs

Edge workloads generate data locally but cloud VMs pay $0.09/GB egress. A factory with 10TB/month of sensor data pays $10,800/year just to move data out of AWS. On-prem edge: $0.

Latency Requirements

Manufacturing SCADA needs <10ms response. Retail POS needs instant transaction processing. Healthcare imaging needs real-time access. Cloud round-trip: 20-100ms. Local KVM: <1ms.

Data Sovereignty

GDPR, HIPAA, and industry regulations require data to stay on-premises. Cloud storage may cross borders. Edge KVM keeps data physically at the site — compliant by design.

Network Unreliability

Remote sites (oil rigs, mines, ships, rural clinics) have intermittent connectivity. Cloud-dependent VMs go down when the link drops. Edge KVM runs autonomously — no internet required.

Cost Multiplier Effect

Every edge site multiplies licensing. 50 sites x vSphere + vCenter = financial disaster. K3s + KVM = $0 per site. Scale to 500 sites with no software cost increase.

The answer: Move workloads from centralized VMware/cloud platforms to lightweight edge infrastructure powered by KVM + K3s + KubeVirt. h2kvm + hypersdk automates the entire journey.

  • Any Linux distro (Fedora, RHEL, Ubuntu)

  • h2kvm generates libvirt XML
  • virsh define + start

  • K3s (single binary, 512MB RAM)
  • KubeVirt for VM workloads

  • Container + VM convergence
  • Cloud-native: K8s APIs everywhere

Option C: Hybrid

  • Some VMs on standalone KVM
  • Others on K3s + KubeVirt
  • h2kvm dual-target pipeline
  • Same tool handles both
  • Flexible: mix per workload needs
  • Best for: mixed workload sites

Cloud Repatriation to Edge

Bring workloads home from AWS, Azure, and GCP to on-premises edge infrastructure.

Why Repatriate to Edge?

Egress Costs Are Hidden Taxes

AWS charges $0.09/GB outbound. A factory site pushing 5TB/month of data pays $5,400/year just in egress — more than the edge hardware costs. On-prem: $0 egress, forever.

Cloud Bills Only Go Up

Reserved instances expire. Spot instances get terminated. Pricing changes annually. Edge KVM has fixed, predictable costs — buy hardware once, run for 5+ years.

Latency-Sensitive Workloads

IoT gateways, real-time analytics, POS systems, SCADA controllers — these need sub-10ms response. Cloud adds 20-100ms of unavoidable latency. Edge KVM: <1ms.

Offline Capability

Edge sites must operate during network outages. Cloud VMs are useless without connectivity. Edge KVM runs autonomously — syncs when the link comes back.

Example: Edge Migration YAML Config

# edge-factory-vm.yaml — Convert VMware VM for edge deployment
cmd: vsphere
vcenter: vcenter.hq.corp
vs_action: export_vm
vs_vm: factory-scada-01
output_dir: ./edge-images
out_format: qcow2
flatten: true
compress: true                  # Smaller image for shipping to edge
regen_initramfs: true           # Inject VirtIO for KVM
emit_domain_xml: true           # Generate libvirt XML (for pure KVM sites)
deploy_k8s: true                # Also generate KubeVirt manifest (for K3s sites)
boot_test: true                 # Verify VM boots before shipping

Dual target in one run: emit_domain_xml + deploy_k8s generates both libvirt XML (for pure KVM edge sites) and KubeVirt manifests (for K3s edge sites) from a single conversion. Deploy the right format per site.
